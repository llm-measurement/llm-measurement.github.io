Are all our requests actually in the spend log?

8 exported rows versus 9 daily requests: 1 missing row.

Run it on your data

Connect fleetdiff v0.12.0 to your existing LiteLLM PostgreSQL database with --litellm-db --daily. It compares request-level spend rows with daily request counts from one read-only snapshot, then removes the temporary export. No psql or model API key is needed. The paired psql export remains an alternative; a Usage dashboard export is not a substitute for request-level rows.

1. Install fleetdiff v0.12.0

Requires curl, gh, shasum and tar on Linux or macOS (amd64 or arm64). Install gh; it need not be signed in. The installer verifies the v0.12.0 release archive, checksums and attestations. Start in a private working directory without an existing bin folder. For manual installation, see release verification.

set -eu
curl -fsSLo install-fleetdiff.sh https://raw.githubusercontent.com/llm-measurement/fleetdiff/6089061c931fa19fac876e40b3809fdea4792ab8/scripts/install.sh
sh install-fleetdiff.sh v0.12.0 ./bin
./bin/fleetdiff --version

2. Compare your database's row counts

Have an administrator review the released read-only role setup. In addition to the selected LiteLLM_SpendLogs columns, daily mode needs SELECT (date, api_requests, successful_requests, failed_requests) on public."LiteLLM_DailyUserSpend". No write or whole-table grant is needed. The projection targets LiteLLM v1.104.0.

Set DATABASE_URL_FILE to an approved credential file outside the checkout: mode exactly 0600, owned by the effective user, with no symlink path components. Leave FLEETDIFF_LITELLM_DATABASE_URL unset so exactly one credential source is active. Keep the URL out of commands, shell history and reports. Remote connections require sslmode=verify-full, with sslrootcert when needed; explicit sslmode=disable is limited to numeric loopback or Unix sockets. Native mode does not use PostgreSQL service files or inherited PG* settings; see credentials and connection settings.

./bin/fleetdiff investigate --litellm-db --daily \
  --database-url-file "${DATABASE_URL_FILE:?set the approved credential file path}" --group-by key

The default compares the last 14 complete UTC days as two seven-day periods, ending at today's UTC midnight. To choose other completed days, supply both --before-period and --after-period with equal-length, ordered, non-overlapping periods bounded at UTC midnight. Sparse logs do not prove full coverage.

Temporary exports use private 0700 directories and 0600 files and are removed after analysis. To retain both CSVs, add --keep-export NEWDIR with a new destination under a trusted parent directory. Retained exports contain grouping identities and must stay private; reports use aliases.

Manual psql alternative or existing paired exports

Requires curl, psql and approved read-only access to LiteLLM_SpendLogs and LiteLLM_DailyUserSpend, configured as the PostgreSQL service litellm_readonly. Set START_UTC and END_UTC to 16 days of completed UTC dates, with both bounds at midnight (for example 2026-09-23T00:00:00Z and 2026-10-09T00:00:00Z). The end bound is exclusive. Use a private working directory without existing coverage-helper or litellm-coverage-export folders.

set -eu
umask 077
mkdir ./coverage-helper
for file in export-coverage.sh export.sql daily-projection.sql; do
  curl -fsSLo "./coverage-helper/$file" \
    "https://raw.githubusercontent.com/llm-measurement/fleetdiff/v0.12.0/examples/litellm-spend/$file"
done
sh ./coverage-helper/export-coverage.sh ./litellm-coverage-export \
  "${START_UTC:?set the export start at UTC midnight}" \
  "${END_UTC:?set the export end at UTC midnight}"

The helper creates a new private directory and exports both CSVs in one read-only, repeatable-read transaction. It refuses an existing directory and writes through separate file descriptors. Keep the three helper files together. The daily CSV contains only dates and request counts; the spend CSV retains grouping identities but excludes prompts, responses and whole metadata objects. Keep both exports and private-psql.out/private-psql.err private.

Compare the paired exports with the installed binary:

./bin/fleetdiff investigate \
  --litellm-spend ./litellm-coverage-export/spend.csv \
  --litellm-daily-spend ./litellm-coverage-export/daily.csv --group-by key

File mode's default compares two complete seven-day periods inferred from the export; the 16-day export leaves room for both. For shorter exports, add explicit --before-period and --after-period dates. Coverage appears before the usage comparison. The released row-coverage guide defines the counts and export contract. To investigate which models and keys changed usage, see LiteLLM spend.

What you'll see

Exact opening output from the synthetic sample below; your counts will reflect your exports.

Spend-log row coverage (relative to LiteLLM daily request counts):
  2026-10-07 UTC: 8 exported rows; 9 daily requests (8 successful, 1 failed); 1 missing row.
  2026-10-08 UTC: 1 exported row; 1 daily request (1 successful, 0 failed); counts match.
Token and spend totals below use exported rows only.

The first day has one fewer spend row than daily requests; the next day matches. All selected request rows count, including failed records and call types excluded from token analysis. Days follow request startTime in UTC. fleetdiff does not fill in missing tokens, spend or contributor totals.

Add --format json for per-day counts and status under row_coverage.days. A missing daily row is unknown, not zero; partial UTC days have no inferred missing-row count. Extra exported rows are a discrepancy to review, not a negative missing count.

The motivating reports describe spend rows lost when provider response IDs collide and reported spend-log row loss under sustained concurrency. The released fixture records the response-ID collision case; it does not validate detection of the reported under-load failure.

No data handy? Try the sample

Requires curl, gh, shasum and tar, with the same supported platforms as above. No Git checkout, Go build, database or model calls are needed. Run in a fresh directory.

set -eu
umask 077
mkdir fleetdiff-row-coverage
curl -fsSLo fleetdiff-v0.12.0.tar.gz \
  https://codeload.github.com/llm-measurement/fleetdiff/tar.gz/refs/tags/v0.12.0
tar -xzf fleetdiff-v0.12.0.tar.gz --strip-components=1 -C fleetdiff-row-coverage
cd fleetdiff-row-coverage
sh scripts/install.sh v0.12.0 ./release
./release/fleetdiff investigate \
  --litellm-spend examples/litellm-spend/coverage_runtime_spend.csv \
  --litellm-daily-spend examples/litellm-spend/coverage_runtime_daily.csv \
  --before-period 2026-10-07 --after-period 2026-10-08

The released spend CSV, daily CSV and verification record come from a synthetic workload through pinned LiteLLM v1.104.0's proxy and database writers.

Limits

Use the same database scope, date bounds, filters and retention for both inputs, and let asynchronous writers settle before exporting completed days. A shared snapshot aligns reads, not separate write completion times. Daily counts are a second accounting path, not an independent request oracle: matching counts cannot reveal requests omitted from both paths. In the pinned runtime, disabling failure logging omitted failed requests from both tables, while successful response-cache hits counted in both without a provider call. These are logged spend-transaction counts, not all incoming requests or provider sends. Recheck other LiteLLM versions and logging configurations; a shortfall identifies records to investigate, not its cause.

This example compares exported rows with recorded daily counts; it leaves token and spend totals unchanged.
