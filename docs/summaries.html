Why summaries instead of raw logs

Keep raw logs where you need the full record. Share summaries when you need combined usage, distinct-user counts and the contributors behind a change without sharing the underlying user or session identities.

A raw-data system can compute exact answers. The measured distinction here is what can be shared and retained without raw identities: compatible sketches can be merged across producers and time windows, while the original records stay with their owner.

Count people across tools without adding them twice

In one lab's released Claude Code and Codex records, the platforms contained 46 and 26 user pseudonyms, with a union of 52. Adding the platform counts gives 72. Merging compatible distinct-user sketches estimates the union instead. Data, method and reproduction.

This works when producers agree on the identity meaning, canonicalization, hash domain and protected key. It does not discover that unrelated account IDs belong to the same person. The released labels in this test share a namespace; they are not independently verified people.

Ask about a date range without reopening every record

Daily summaries can be merged for a week, a month or a longer investigation. Across the coding records, the experiment queried every 7-, 28- and 90-day range from the retained summaries and checked each distinct-count estimate against the exact released-label union. This small-population result is separate from the scale test below. Data, method and reproduction.

The retained platform summaries occupied 2,087,216 bytes over 305 days, compared with 1,245,532,297 bytes of uncompressed source records. Both figures are uncompressed; the source download itself was 100,939,722 bytes. The summaries retain selected measurements, not everything in those records. Storage method and reproduction.

Keep the measurement size bounded as identities grow

In the synthetic scale test, a distinct-count sketch and token-weighted ranking for one million synthetic users occupied 27,221 serialized bytes. The measured top-ranking recall was 100% for the top 20 across three Zipf workloads. That is an observed result for those workloads, not a perfect-ranking promise. Workload, machine and reproduction.

The selected sketch profiles set their capacity. A growing user population does not require a metric label or an exact table entry for every user. For small populations, however, a raw list can be smaller: the coding-data daily comparison averaged 116 bytes for the exchanged distinct sketches versus 103 bytes for the raw lists. Bounded size and the sharing boundary are the reasons to use a sketch, not a claim that it always wins on bytes. Comparison method.

Find the contributors behind an increase

A token-weighted ranking retains heavy contributors as keyed identifiers with lower and upper bounds. Comparing compatible windows gives a bounded change for each tracked contributor. In the adjacent-day coding-data checks, all 19,862 checked user/session deltas stayed within their bounds; the applicable growth-share checks also contained the reference. Reference comparison and reproduction.

This answers who accounts for the recorded increase. It does not explain intent or predict that a concentrated increase will continue. The producer can investigate a keyed identifier locally using its own records.

Share measurements with an analyst, not an identity table

The experiment's analyst used summary files with access to raw records and the network denied. The privacy checks inspected serialized bytes, decoded sketch payloads and analyst outputs for known source identifiers and planted values. Privacy method and reproduction.

Keyed identifiers remain linkable. Protect the hashing key and control access to summaries as well as logs. The experiment uses a public test key for reproducibility; it establishes field exclusion, not anonymity. Aggregate measurements also reveal activity.

Choose what to retain

Use raw records for exact investigations and questions you have not selected in advance. Use summaries for repeated measurements over the dimensions you chose: totals, distinct identities and leading contributors. Keep exact records for billing. The two can coexist; the collector can fan out the original spans to your existing backend while exporting summaries.

Start with a user and session investigation, a distinct-user example, or the per-user cardinality guide.

Contributor bounds

Use the pinned coding dataset and recorded environment. Check each key appearing in either adjacent day's exact user/session table, including keys not retained as candidates. The change interval is the after lower bound minus the before upper bound, through the after upper bound minus the before lower bound. For positive total growth, divide both endpoints by that exact growth. A share can exceed the whole increase when other contributors decline.
