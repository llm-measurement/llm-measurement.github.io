Why summaries instead of raw logs

Merge usage across tools, count distinct users, and find the contributors behind a change from retained summaries. In the coding-agent records measured here, 305 days fit in 2.1 MB of summaries, against 1.25 GB of source records. Data and reproduction.

Combine users across tools

Claude Code and Codex contained 46 and 26 user labels, with a union of 52. Adding the counts gives 72. The merged distinct-user estimate stayed within 0.0007 users of the exact union on all 305 days. Method and reproduction.

Query retained history

The summaries answered 793 range queries across 7, 28, 90 days, with maximum absolute error 0.0034 users. Median batch time averaged 0.026 ms per query or less for each range length. The query merged daily states already loaded into memory. Method and reproduction.

Keep state small as identities grow

For 1,000,000 synthetic users, the distinct-count and token-ranking sketches occupied 27,221 bytes, against 26.5 MB of exact keyed-table JSON. Across 3 seeds, observed distinct-count errors were approximately 0.4% to 0.7%, with 100% top-20 recall. Workload and reproduction.

How it works

These are standard mergeable-sketch properties (Agarwal et al., PODS 2012), also used in Apache DataSketches and BigQuery HLL_COUNT, measured here on LLM usage records.

What the numbers mean

  • Compatible identities. Merging requires the same identity field, canonicalization, hash domain and key, plus compatible measurement contracts. The coding records share a user-label namespace; these are released pseudonyms, not verified people.
  • Keyed and pseudonymous, not anonymous. Whoever holds the key can hash a known ID and test it against exposed hashes. Cardinality sketches can also leak membership information; see Desfontaines, Lochbihler and Basin, PoPETs 2019. Protect the key and summary access. This experiment's public test key and known-pattern scans establish field exclusion, not anonymity.
  • Different retained information. A raw-data system can compute exact answers. Summaries answer chosen questions while raw records answer new ones and remain the source for billing. The byte comparison is selected summary measurements against full source records, not lossless compression. For a few dozen users, the raw lists were smaller: 117 versus 103 bytes per day for sketches and lists respectively.
  • Different guarantees. Distinct counts are statistical estimates; contributor bounds are deterministic. The reported errors and flag agreement describe these workloads, not guarantees of perfect accuracy or anomaly detection.
  • Scope. One lab's Claude Code and Codex records, synthetic scale workloads, and one machine. Sizes use decimal MB and GB; sketch wire bytes exclude process RAM. Query timings are batch averages, not a bound on every query. Complete source collection and provider billing were not independently verified. Source attribution implies no endorsement.
