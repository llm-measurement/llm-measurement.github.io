LiteLLM session over its budget? Check what the budget counts

Review recorded session spend against a supplied cap, see which session IDs span keys or agents, and check whether the export records budget rejections.

Run it on your data

Start with request-level spend logs from one LiteLLM application and one LiteLLM deployment sharing one cache. Use the read-only SQL export from fleetdiff v0.11.0, including session_id, agent_id and the content-free rejection_kind column. The projection is pinned to LiteLLM v1.104.0. Keep the export private and use its path below.

Requires curl, gh, shasum and tar on Linux or macOS (amd64 or arm64). Install gh; it need not be signed in. The installer verifies the released binary. Reviewers can use the manual verification steps.

curl -fsSLo install-fleetdiff.sh https://raw.githubusercontent.com/llm-measurement/fleetdiff/v0.11.0/scripts/install.sh
sh install-fleetdiff.sh v0.11.0 ./bin
./bin/fleetdiff investigate --litellm-spend ./spend.csv --session-budget-usd 1.00

Replace 1.00 with the USD cap you want to review. This mode groups by session ID alone, matching the pinned limiter's counter unit, across keys, teams and agents. It reads local files; it does not configure or enforce a budget.

The default includes complete UTC days in the file, or its labeled observed span when no complete day is present. Add --period YYYY-MM-DD or a UTC interval to choose a period. If you changed LITELLM_MAX_BUDGET_PER_SESSION_TTL, match --session-counter-window to that duration (default 1h). Older exports work too; missing rejection classification is shown as unknown.

What you'll see

Example output from the synthetic sample below; your numbers will reflect your export and supplied cap.

3 of 4 sessions with complete recorded spend exceed the supplied USD 1.00 cap.

The report prints the exact period immediately below its result. The short sample uses its observed span. Sessions active near an uncovered file edge are marked possibly clipped; a matching session ID with rows outside a selected period is marked clipped.

Observed session totals
Recorded USD: p50 1.10; p95 1.60; max 1.60 (n=4, exact nearest-rank).
Logged model calls: p50 2; p95 6; max 6 (n=4, exact nearest-rank).

Half the observed sessions have recorded spend at or below USD 1.10. Each distribution prints its own sample count; incomplete spend is kept separate. The largest sessions use keyed aliases.

Cap review
Above-cap sessions with no recorded session-budget rejection: 2.

Start with these review items. Check last-call or parallel-call overshoot, the counter window, agent budget configuration and failure logging. The report also counts sessions with recorded budget or iteration rejections.

Sessions spanning more than 3600 seconds between first and last positive-spend request starts: 1.
  session-1: 4000 seconds.

This is the elapsed time in the records; the duration line alone cannot establish that a reset occurred.

Session IDs observed under multiple keys, teams or agents: 1. Each addresses the same counter key; shared storage and agent budget configuration determine actual tracking.
  session-1: keys=2, teams=2, agents=2.

The same session ID can join activity across agents. Review these aliases when you expected separate session budgets.

Why sessions end up over the cap

  • The pinned LiteLLM v1.104.0 limiter checks spend already recorded before each call (current_spend >= max_budget) and adds positive cost after a successful call. The call that crosses the cap can run; concurrent calls can all pass while recorded spend is still below it. See the upstream concurrency report.
  • The counter key uses the session ID alone, so budget-tracked agents using that ID share the counter. See the upstream report on shared session limits across agents.
  • LiteLLM documents a one-hour default counter expiry, configurable with LITELLM_MAX_BUDGET_PER_SESSION_TTL.

No data handy? Try the sample

Requires curl, gh, shasum and tar. Install gh; it need not be signed in. The example uses a released binary and synthetic request-level records.

curl -fsSLo fleetdiff-source.tar.gz https://github.com/llm-measurement/fleetdiff/archive/refs/tags/v0.11.0.tar.gz
tar -xzf fleetdiff-source.tar.gz
cd fleetdiff-0.11.0
sh scripts/install.sh v0.11.0 ./release
./release/fleetdiff investigate --litellm-spend examples/litellm-spend/session-budget.csv \
  --session-budget-usd 1.00

Source and reproduction: released synthetic CSV, session-budget guide, and the verification record.

Recorded session totals are review evidence, not an enforcement verdict or completed-task costs. Missing identities stay unattributed; absent recorded rejections do not prove that no rejection occurred.
