Which user is driving my LLM token spike?

Compare two periods to see which users and sessions account for a token increase.

  • Your collector summaries
  • Get summary windows
  • A LiteLLM export
  • Sample data

Run it on your data

Save token-weighted user/session summaries in ./before and ./after. Use one hashing key and replace app with your producer name.

Linux or macOS; needs curl, gh, shasum and tar. The installer checks the release before unpacking it.

curl -fsSLo install-fleetdiff.sh https://raw.githubusercontent.com/llm-measurement/fleetdiff/0d7db95c5bb3013f8c564c91fbb07b6235a2664e/scripts/install.sh
sh install-fleetdiff.sh v0.12.1 ./bin
./bin/fleetdiff investigate --before ./before --after ./after --expected app

See changes in attempts, tokens per attempt and contributors.

Get summary windows

Enable user/session rankings, then retain summary windows. For LiteLLM, use the gateway recipe.

Use a LiteLLM export

Use request-level spend.csv from the export recipe.

./bin/fleetdiff investigate --litellm-spend ./spend.csv --group-by user

Export 16 days for two seven-day UTC periods. user means key owner; use --group-by end-user for application users.

Try the sample

Linux or macOS; needs curl, gh, shasum and tar. The installer checks the release before unpacking it.

curl -fsSLo fleetdiff-source.tar.gz https://github.com/llm-measurement/fleetdiff/archive/refs/tags/v0.12.1.tar.gz
tar -xzf fleetdiff-source.tar.gz
cd fleetdiff-0.12.1
sh scripts/install.sh v0.12.1 ./release
./release/fleetdiff investigate --before examples/sessions/data/before \
  --after examples/sessions/data/after --expected app

What you'll see

Example output from this synthetic sample; your values will reflect your input.

fleetdiff shows the split between more model attempts and more tokens per attempt. In this example, the application's reported total rises from 400 to 3,300 tokens.

1 of 8 tracked sessions flagged for review: 90.91% of attributed tokens.
Reported tokens: 400 -> 3300; model attempts: 4 -> 13.
  +1592 tokens from attempt count; +1308 tokens from tokens per attempt.
  Tokens per attempt: 100.00 -> 253.85.

One user adds 3,000 reported tokens, accounting for 90.91% of the after-period's attributed tokens.
