How do I detect anomalies in LLM token consumption?

Scan retained summary windows to find unusual token use, concentrated users or sessions, tool errors and gaps in usage reporting.

  • Your summary history
  • Start retaining windows
  • Sample data

Run it on your data

Put complete summary windows in ./summary-history: 24 baseline windows plus recent ones. Use consistent hashing and accounting settings; replace app with your producer name.

Linux or macOS; needs curl, gh, shasum and tar. The installer checks the release before unpacking it.

curl -fsSLo install-fleetdiff.sh https://raw.githubusercontent.com/llm-measurement/fleetdiff/78c6448de2f11e96ca63fb5d6ecff2ad2364304a/scripts/install.sh
sh install-fleetdiff.sh v0.14.0 ./bin
./bin/fleetdiff scan ./summary-history --expected app --recent 2

Exit 3 means findings; 0 means none. See the scan guide for thresholds.

Start retaining windows

Set up summary export and retention with collector v0.6.2 / chart 0.6.2. Schedule scans as new windows arrive.

Try the sample

Linux or macOS; needs curl, gh, shasum and tar. The installer checks the release before unpacking it.

Go 1.26.9 or later generates the synthetic windows.

curl -fsSLo fleetdiff-source.tar.gz https://github.com/llm-measurement/fleetdiff/archive/refs/tags/v0.14.0.tar.gz
tar -xzf fleetdiff-source.tar.gz
cd fleetdiff-0.14.0
sh scripts/install.sh v0.14.0 ./release
GOWORK=off go run ./examples/scan --out ./synthetic-windows
./release/fleetdiff scan ./synthetic-windows --expected app --recent 2 \
  --as-of 2026-10-04T00:30:00Z

2026-10-04T00:29:00Z
  Missing usage: 40.00% of model attempts; typical 0.00% (coverage change, not lower usage).

When a window reports missing usage, check the fields in a local capture: Do my LLM traces record token usage and user IDs?
