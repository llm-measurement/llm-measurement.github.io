Usage jumped? Compare two periods and see which users and sessions account for the increase.

Run it on your data

A request-level LiteLLM export such as spend.csv, or read-only access to the proxy’s Postgres database to create one. Use the read-only export recipe; the Usage dashboard’s daily aggregate is a different format.

Requires curl, gh, shasum and tar on Linux or macOS (amd64 or arm64). The installer downloads and verifies fleetdiff v0.7.0; analysis reads your local file. For a manual installation, see release verification.

curl -fsSLo install-fleetdiff.sh https://raw.githubusercontent.com/llm-measurement/fleetdiff/v0.7.0/scripts/install.sh
sh install-fleetdiff.sh v0.7.0 ./bin
./bin/fleetdiff investigate --litellm-spend ./spend.csv --group-by user

The default compares the two most recent complete seven-day UTC periods inside the file; export 16 days. For shorter files, pass --before-period and --after-period. user is the key owner; use --group-by end-user for application users.

For continuous measurement, retain collector summary windows with user and session rankings and a consistent hash key. With your producer inventory named app:

./bin/fleetdiff investigate --before ./before --after ./after --expected app

No data handy? Try the sample

Requires Git, curl, gh, shasum and tar. Linux or macOS, amd64 or arm64. No collector, Docker or model API key is needed for the sample.

git clone --depth 1 --branch v0.7.0 https://github.com/llm-measurement/fleetdiff.git fleetdiff-token-spike
cd fleetdiff-token-spike
sh scripts/install.sh v0.7.0 ./release
./release/fleetdiff investigate --before examples/sessions/data/before \
  --after examples/sessions/data/after --expected app

Reading the result

In this synthetic example, one user adds 3,000 reported tokens while the application's total rises from 400 to 3,300.

fleetdiff shows both the contributors and the split between more model attempts and more tokens per attempt.

To see who uses the most overall, rather than who changed, see Who is tokenmaxxing?

Use your own application

Enable token-weighted user_key and session_key rankings in the released collector, retain two complete summary windows, and pass their directories as --before and --after. Set --expected to your actual producer inventory and keep the hashing key consistent across the comparison.

For a gateway setup, start with the LiteLLM recipe. To keep watching, scan retained history.

Source and reproduction: released session fixtures and generator. Verification record.
