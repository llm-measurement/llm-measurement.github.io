Keep user identities in keyed rankings, and use a small set of non-sensitive labels for Prometheus. The genaisketch connector can report distinct users and token-heavy users without creating a series for every user.

The check below finds an enduser.id label in a synthetic collector configuration. fleetdiff points to the YAML setting that needs changing.

Check a configuration

Requires Git, curl, gh, shasum and tar. Linux or macOS, amd64 or arm64. The installer verifies the v0.5.0 release before extraction.

git clone --depth 1 --branch v0.5.0 https://github.com/llm-measurement/fleetdiff.git fleetdiff-cardinality
cd fleetdiff-cardinality
sh scripts/install.sh v0.5.0 ./release
./release/fleetdiff diagnose - < examples/diagnose/unsafe.yaml

The relevant output is:

2 problems to fix:
  connectors.genaisketch.operation_filter.llm_operations (line 10): Keep only model operations (chat, generate_content, text_completion, embeddings), each once. Tool and agent operations count as model attempts if included.
  connectors.genaisketch.slices[0].keys (line 12): enduser.id is a metric label; remove it from slices and use a hashed field instead.

Exit code 3 means the configuration has a blocking finding. It is the expected result for this example.

Keep the user answer

Remove the user identity from slices. Configure a hashed user_key and enable its token-weighted ranking with topk_keys. The ranking goes to snapshot logs and summary files; Prometheus receives aggregate metrics. Limit model or route slices with the connector's configured cardinality cap.

Follow the v0.3.1 user-ranking configuration and the slice configuration reference. Then use fleetdiff to compare users across windows.

What the numbers mean

This is a static configuration check, not a measurement of live series count. Keyed hashes are pseudonymous. Restrict access to the hashing secret, rankings and summary files. Trace fan-out preserves original spans, so apply any required content redaction before forwarding them.
