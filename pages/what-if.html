Checked synthetic example: moving half of the covered claude-sonnet-5-5 usage to gpt-6.1-sol reprices the period from $0.154400 to $0.109398 to $0.147974, depending on workload assumptions.

Run it on your data

Start with a request-level LiteLLM CSV, JSON or JSONL export containing the model, timestamp, input tokens, output tokens, cache-read input tokens and cache-write input tokens. Use the read-only export recipe if needed; the Usage dashboard's daily aggregate is a different format. Keep exports and identity mapping files private.

1. Install fleetdiff v0.10.0

Requires curl, GitHub CLI (gh), shasum and tar on Linux or macOS, amd64 or arm64. No Go compiler or model API credentials are needed. GitHub CLI need not be signed in. Use a working directory without an existing bin folder. The installer verifies the released archive and checksum manifest before extraction; see manual release verification to review those steps.

umask 077
curl --proto '=https' --tlsv1.2 -fsSLo install-fleetdiff.sh \
  https://raw.githubusercontent.com/llm-measurement/fleetdiff/v0.10.0/scripts/install.sh
sh install-fleetdiff.sh v0.10.0 ./bin

2. Re-price a completed period

Use spend.csv for your export, or change the path below. Set PERIOD_UTC to a completed UTC date such as 2026-10-07, or a half-open interval such as 2026-10-01T00:00:00Z/2026-10-08T00:00:00Z. Choose source and target model IDs supported by the dated price table.

./bin/fleetdiff what-if --litellm-spend ./spend.csv \
  --period "${PERIOD_UTC:?set a completed UTC date or interval}" \
  --from claude-sonnet-5-5 --to gpt-6.1-sol --fraction 0.5

0.5 moves half the covered token volume, retaining its observed input, output and cache composition. It does not select particular requests. Analysis reads local files only and makes no model calls. For several moves or your applicable price overrides, see the released what-if guide.

Use your workload mix

A workload map assigns recorded keys or teams to qa, extraction or coding. It does not infer the task from token counts. Put the following shape in a protected workload-map.json, replacing the example selector values with IDs recorded in your export; avoid putting private IDs in shell history.

{
  "version": 1,
  "mappings": [
    {"selector": {"kind": "key", "value": "your-coding-key-id"}, "workload": "coding"},
    {"selector": {"kind": "team", "value": "your-extraction-team-id"}, "workload": "extraction"}
  ]
}
./bin/fleetdiff what-if --litellm-spend ./spend.csv \
  --period "${PERIOD_UTC:?set a completed UTC date or interval}" \
  --from claude-sonnet-5-5 --to gpt-6.1-sol --fraction 0.5 \
  --workload-map ./workload-map.json --format json

Mapped records use their assigned workload; unmapped records remain under all three measured assumptions. Conflicting key/team mappings are rejected. A model pair without a measured output factor stays at level 1; no reverse or transitive factor is invented.

Limits

  • This re-prices recorded usage under explicit model, cache and workload assumptions. It is not a forecast or an invoice.
  • The factors are geometric mean paired ratios from public benchmark tasks; your traffic may differ. Individual requests vary widely, and the per-request range test failed.
  • The displayed ranges propagate mean-factor intervals. They are not validated prediction intervals for your requests or workload, and the combined range is not a joint 95% confidence interval.
  • No quality equivalence is claimed. Lower modeled cost does not establish that a target model performs the same work equally well.

The released benchmark evidence records model IDs, fit counts, dates, dataset and license pins, estimator and price sources; the factor table links each measured pair to that provenance.
