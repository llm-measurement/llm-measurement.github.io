See which models served each original LiteLLM route, how their request, token and recorded-spend shares changed, and where attribution is missing.

Run it on your data

Connect to your existing LiteLLM Postgres database with approved read-only access. fleetdiff exports routing details automatically, audits the private snapshot locally and removes the temporary export. No psql or model calls are needed. An existing request-level CSV, JSON or JSONL export also works through the manual path below.

1. Install fleetdiff v0.12.0

Requires curl, gh, shasum and tar on Linux or macOS, amd64 or arm64. GitHub CLI need not be signed in. Start without an existing bin folder. The pinned installer verifies the release archive, checksums and attestations; see manual release verification.

curl -fsSLo install-fleetdiff.sh https://raw.githubusercontent.com/llm-measurement/fleetdiff/65990e302913fb960db3ba3a53cb4633bef63117/scripts/install.sh
sh install-fleetdiff.sh v0.12.0 ./bin

2. Audit your database

Have your administrator provision the read-only role and column grants. Set DATABASE_URL_FILE to an approved regular credential file owned by your effective user, mode exactly 0600, with no symlink path components. Keep it outside your checkout and leave FLEETDIFF_LITELLM_DATABASE_URL unset when using the file option.

./bin/fleetdiff investigate --litellm-db \
  --database-url-file "${DATABASE_URL_FILE:?set the approved credential file path}" --routing-audit

This compares the last 14 complete UTC days as two adjacent seven-day periods, ending at today's UTC midnight. Empty or sparse logs do not establish coverage. Routing fields are included automatically; missing source attribution stays unknown. Add --keep-export NEWDIR only when you need to retain the private export; the destination must not exist.

Alternatively, let your approved secret mechanism supply FLEETDIFF_LITELLM_DATABASE_URL and omit --database-url-file. Never pass a literal URL argument or type a password into shell history. Remote TLS requires sslmode=verify-full, with optional sslrootcert; only numeric loopback or Unix sockets allow explicit plaintext. Native mode ignores inherited PG* settings, pgpass and service files. See credential sources, URL options and private-export handling. Use psql for administrator-approved services or client certificates.

Manual psql alternative or an existing export

Requires curl, psql and approved read-only access configured as the PostgreSQL service litellm_readonly. Set START_UTC and END_UTC to UTC RFC3339 bounds covering both comparison periods, such as 2026-10-01T00:00:00Z and 2026-10-03T00:00:00Z; the end is exclusive. Start in a private directory without an existing routing-export folder.

set -eu
umask 077
curl -fsSLo export.sql https://raw.githubusercontent.com/llm-measurement/fleetdiff/v0.12.0/examples/litellm-spend/export.sql
mkdir ./routing-export
psql 'service=litellm_readonly' -Xq -v ON_ERROR_STOP=1 \
  -v start_utc="${START_UTC:?set the export start in UTC}" \
  -v end_utc="${END_UTC:?set the export end in UTC}" \
  -v routing_details=true -v csv_file='./routing-export/spend.csv' -f export.sql \
  >./routing-export/private-psql.out 2>./routing-export/private-psql.err
printf 'Exported routing details to ./routing-export/spend.csv\n'

The opt-in flag adds original_model_group, attempted_fallbacks and internal_call_origin from the tested LiteLLM v1.104.0 metadata paths. The read-only projection also includes agent, selected-model and deployment fields; it excludes prompts, responses and whole metadata objects. Keep the export and database diagnostics private. Review the pinned export contract before using another writer version.

Compare two chosen periods from a file

Set BEFORE_PERIOD_UTC and AFTER_PERIOD_UTC to completed UTC dates, such as 2026-10-01 and 2026-10-02, or equal-duration, ordered, nonoverlapping half-open UTC intervals. Use the export above or replace its path with your file. File-based analysis stays offline.

./bin/fleetdiff investigate --litellm-spend ./routing-export/spend.csv \
  --before-period "${BEFORE_PERIOD_UTC:?set the before UTC date or interval}" \
  --after-period "${AFTER_PERIOD_UTC:?set the after UTC date or interval}" \
  --routing-audit

The audit groups by original route. --group-by still controls contributor rankings, not this table. To separate known agents within each route, read a fresh database snapshot as JSON using the same chosen periods:

./bin/fleetdiff investigate --litellm-db \
  --database-url-file "${DATABASE_URL_FILE:?set the approved credential file path}" \
  --before-period "${BEFORE_PERIOD_UTC:?set the before UTC date or interval}" \
  --after-period "${AFTER_PERIOD_UTC:?set the after UTC date or interval}" \
  --routing-audit --routing-by route-agent --format json

Routes and agents use aliases by default. Add --show-labels only for a local report that needs their recorded names, and review it before sharing. Exact public model names from the bundled price catalog are readable; private model and deployment names stay aliased, including with that flag.

Select a route or agent

Set ORIGINAL_ROUTE privately to the recorded original route, not its report alias. A scope filters the investigation and counts nonmatching known rows separately from rows whose identity is unknown.

./bin/fleetdiff investigate --litellm-db \
  --database-url-file "${DATABASE_URL_FILE:?set the approved credential file path}" \
  --before-period "${BEFORE_PERIOD_UTC:?set the before UTC date or interval}" \
  --after-period "${AFTER_PERIOD_UTC:?set the after UTC date or interval}" \
  --scope-route "${ORIGINAL_ROUTE:?set the recorded original route}" --routing-audit

Use --scope-agent instead for one agent. Use one scope at a time with both explicit periods; scopes cannot be combined with daily row coverage or session grouping. In model what-if, the same scope restricts the traffic moved while keeping the covered baseline for other traffic. An explicit workload map supplies the task class; route or agent names do not.

Limits

  • Model identity is the gateway-selected model with a recorded deployment ID, not independent confirmation of the provider's model or final bill. Failure-row usage has unknown finality.
  • Different models behind a route show routing variation, not its cause. Recorded fallback counters do not reconstruct physical attempts, and the audit cannot recover missing requests.
  • Unknown models remain in share denominators; missing usage and spend are reported separately. A zero denominator gives an unknown share. An absent original route stays unknown rather than being inferred from a recovery route.
  • Only pass_through_endpoint rows marked autorouter_classifier count as classifier overhead. Other unsupported rows stay separate. The audit does not establish causal savings or quality equivalence.

This synthetic example checks recorded routing distributions and attribution coverage, not a performance or savings measurement.
