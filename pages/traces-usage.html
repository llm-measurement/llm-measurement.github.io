fleetdiff inspect reads a local OTLP capture and reports which usage and identity fields are present, missing or zero.

Run it on your data

Put your OTLP JSON/JSONL or protobuf capture at ./traces.jsonl.

Linux or macOS; needs curl, gh, shasum and tar. The installer checks the release before unpacking it.

curl -fsSLo install-fleetdiff.sh https://raw.githubusercontent.com/llm-measurement/fleetdiff/6089061c931fa19fac876e40b3809fdea4792ab8/scripts/install.sh
sh install-fleetdiff.sh v0.12.0 ./bin
./bin/fleetdiff inspect ./traces.jsonl

See SDK and LiteLLM capture recipes or the field guide.

Capture from your collector

Add a file exporter to your Contrib collector:

exporters:
  file/inspect:
    path: /private-capture/traces.jsonl
    format: json
    rotation:
      max_megabytes: 4
      max_backups: 1

Create the directory, writable by the collector. Add file/inspect alongside existing trace exporters. Stop and flush the capture, then copy it to ./traces.jsonl. Follow the capture recipe.

What you'll see

Example output from this synthetic sample; your values will reflect your input.

The report starts with the questions this capture can answer and the fields to improve next.

Your traces can fully answer 2 of 7 questions.
Next: Record both input and output usage; resolve invalid, conflicting, or subset-violating values. Declare unavailable usage instead of filling in zeros.

Usage fields

One model attempt is missing token fields. Another has input and output recorded as zero, with no declared origin.

4 model attempts across 6 captured spans; 170 reported tokens.
Usage: 3 complete, 1 missing either field.
Origin unknown: input 4, output 4 attempts.

The zero-valued fields are present, so they are included in the three complete observations. The origin check keeps their source unknown.

User and session fields

All four model attempts have user IDs.

user: ~4 distinct; identity present on 4/4 attempts

Only two of the four attempts have session IDs.

session: ~2 distinct; identity present on 2/4 attempts

The report also lists standard attribute names and uses local aliases for individual users and sessions.
