fleetdiff inspect reads a local OTLP capture and reports which usage and identity fields are present, missing or zero.

Run it on your data

You need an OTLP JSON/JSONL or protobuf capture. If your collector includes the file exporter, add this exporter alongside the existing trace destination for a short authorized capture, then stop the capture and inspect its flushed file:

exporters:
  file/inspect:
    path: /private-capture/traces.jsonl
    format: json
    rotation:
      max_megabytes: 4
      max_backups: 1

Create a private directory writable by the collector, add file/inspect to its trace pipeline’s exporter list, and keep its existing exporters. Keep content capture off and the raw file private. The genaisketch image does not include this exporter; use an existing Contrib collector or the short capture recipe. Put the resulting file at ./traces.jsonl.

Requires curl, gh, shasum and tar on Linux or macOS (amd64 or arm64). Install gh; it need not be signed in. The installer downloads and verifies fleetdiff v0.8.0; analysis reads your local file. For a manual installation, see release verification.

curl -fsSLo install-fleetdiff.sh https://raw.githubusercontent.com/llm-measurement/fleetdiff/v0.8.0/scripts/install.sh
sh install-fleetdiff.sh v0.8.0 ./bin
./bin/fleetdiff inspect ./traces.jsonl

The capture recipes also cover a Python SDK or LiteLLM. Keep the capture local and share the default report instead of the raw file. The inspect guide covers accepted formats and field mappings.

What you'll see

Example output from the synthetic sample below; your values will reflect your input.

The report starts with the questions this capture can answer and the fields to improve next.

Your traces can fully answer 2 of 7 questions.
Next: Record both input and output usage; resolve invalid, conflicting, or subset-violating values. Declare unavailable usage instead of filling in zeros.

Usage fields

One model attempt is missing token fields. Another has input and output recorded as zero, with no declared origin.

4 model attempts across 6 captured spans; 170 reported tokens.
Usage: 3 complete, 1 missing either field.
Origin unknown: input 4, output 4 attempts.

The zero-valued fields are present, so they are included in the three complete observations. The origin check keeps their source unknown.

User and session fields

All four model attempts have user IDs.

user: ~4 distinct; identity present on 4/4 attempts

Only two of the four attempts have session IDs.

session: ~2 distinct; identity present on 2/4 attempts

The report also lists standard attribute names and uses local aliases for individual users and sessions.

No data handy? Try the sample

Requires Git, curl, gh, shasum and tar. Linux or macOS, amd64 or arm64. The sample uses the shipped synthetic capture and the verified v0.8.0 binary; no Go installation is needed.

git clone --depth 1 --branch v0.8.0 https://github.com/llm-measurement/fleetdiff.git fleetdiff-traces-usage
cd fleetdiff-traces-usage
sh scripts/install.sh v0.8.0 ./release
./release/fleetdiff inspect examples/inspect/synthetic-traces.json

Source and reproduction: released synthetic OTLP capture and capture recipes. Verification record.
