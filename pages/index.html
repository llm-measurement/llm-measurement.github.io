LLM Measurement is a set of open-source tools that make everyday questions about LLM usage simple to ask and rigorous to answer. Which users and sessions drove a token spike? How many distinct users did an application have this week? Are the usage records complete? How does usage compare across teams and tools? The tools answer from the telemetry you already collect, without a metric label for every user. Their outputs carry keyed hashes instead of raw user or session IDs.

They are designed with care and built on peer-reviewed sketching algorithms. Rankings come with guaranteed bounds, distinct counts come with a known statistical error, and missing usage is counted separately as missing. Every result on this site comes with the commands to reproduce it.

Questions

Each guide runs released versions on synthetic examples.

  • Which user is driving my token spike?

    Compare two windows and see the users and sessions behind the increase.

  • How do I see LLM usage per user without a metric label for every user?

    Check the labels in your collector configuration and keep user rankings separately.

  • Which windows look unusual?

    Scan usage history for changes in tokens, coverage and contributors.

  • How many distinct users were active?

    Count with keyed measurements that can be merged across workers.

Why summaries instead of raw logs? See the measured sharing and retention properties, with source data and methods.

Using LiteLLM?

Start with the released LiteLLM telemetry recipe. It sends spans through the collector and compares exported summaries with fleetdiff. The Python and Go library also works directly in your own measurement code.

Choose a tool
